# Decision log

Newest first. Add an entry when a choice changes how the app works or how we
work: date (America/New_York), the decision, and why. Link the CHANGELOG entry or
Notion ticket when there is one. Earlier history is in CHANGELOG.md.

| Date | Decision | Reason |
|---|---|---|
| 2026-10-31 | V4's build step lands in **plain JavaScript**, and the TypeScript conversion is a separate ticket and batch straight after it, before the design system starts (docs/V4-PLAN.md §3.1, §9). | Phase 2's only claim is "behaviour identical", certified by the regression suite. A type migration is not just annotation — each real type error is a question about intended behaviour — so landing it in the same commits would leave a red check unable to say which change caused it. Types also buy little in this step: the conversion turns 43 globals into named imports and the bundler already fails on a bad import. Where they pay is component variants and token-typed props in Phases 3–5, so the conversion goes immediately after Phase 2 rather than "someday". The price is one extra pass over the files; the gain is that each pass answers one question. |
| 2026-10-28 | Portraits resolve through the credit, not the character. `MEDIA.performers` maps a performer name to a TMDB profile path; a row uses the character's portrait when the credited performer is the default, the performer map when it is not, and **no photo** otherwise. | Correcting the names alone left the right name under the wrong face, which is worse than both being wrong together. A missing portrait falls back to initials, which `Portrait` already does, so an unknown performer costs a face rather than showing someone else's. Every path added was verified against that person's own credits first. |
| 2026-10-28 | Manual panning ends with a light inertial glide instead of stopping dead, on both the mouse and the touch path. Any press, touch or wheel on the viewport stops it exactly where it is, a slow release does not throw, and `prefers-reduced-motion` disables it. | Asked for: the sudden stop made the Spatial canvas feel unrefined. This **reverses** the earlier rule that manual pan must stay instant, so the comment beside `glideTo` was rewritten rather than left contradicting the code. What that rule protected still holds — the canvas is never moving when you reach for it. A drag now settles a moment after mouseup, so checks that snapshot a camera position must wait for it (see `settleCanvas` in qa/test-camera.js). |
| 2026-10-28 | A performer credit belongs to the title, not the character. Titles may carry `credits` (character id to performer) and `CHARACTERS[id].actor` is only the default. A performer pins as themselves unless they are that character's whole run. | One `actor` per character leaked the current performer into every title: Iron Man credited Don Cheadle as Rhodes, The Incredible Hulk credited Mark Ruffalo and Harrison Ford. Keeping the credit on the title leaves the character's identity, colour and connection thread untouched. The pin rule follows from it — Terrence Howard plays Rhodes in one title of eleven, so pinning him must not open the other ten. |
| 2026-10-28 | Escape clears the pinned character or performer, last in the ladder (after the search box, menus, dialogs, sheets, the pair view and the details). The details rung and the pin rung share **one** listener. | The widget could only be dismissed with its ×. Two listeners broke the one-layer-per-press rule: both see the same press, React re-renders between them for a discrete event, and a listener added to `window` during capture is still called when the event bubbles back to it — so the second ran with a fresh closure, saw nothing in its way, and closed the pin under the details. |
| 2026-10-28 | A pinned subject is either one portrayal or a performer. Picking an actor who plays several characters pins the **actor**: the union of their own roles' titles, named as themselves with their characters underneath. An actor with one role still pins as that character, and picking a character still pins that portrayal. | Making `pickPerson` refuse multi-role actors removed the pinned widget for Jonathan Majors, Hayley Atwell, Paul Bettany and Robert Downey Jr. (who had never had it, two separate identities), which was a worse trade than the rule it protected. A performer's own titles are the titles they are actually in, so exact portrayal still holds and no result implies another actor's work. |
| 2026-10-28 | Notion V3 Tasks gains an **Approved** status, between Awaiting review and Blocked. The user sets it themselves; it clears that ticket's current revision to be committed and pushed to staging, never a merge to `main`, and it lapses if the work changes afterwards. | Approval only existed in chat, so it died with the conversation and the other agent could not see it. A flag on the ticket lets the user approve work whenever they get to it and lets either agent pick it up later. |
| 2026-10-28 | A selected character means one exact portrayal. Its suggestion count, banner, stepper and narrowed catalog all describe that one character; connection lines still thread variants onto their prime identity. | "Peter Parker (Raimi)" offered 1 title and then opened Tom Holland's 13, implying Tobey Maguire was in them. Keeping the threading on the prime leaves arcs like Kang's continuous on the canvas. It also narrows Kang, Peggy and Vision. Picking an actor was briefly made to fall back to a text search, which the row above replaced the same day. |
| 2026-10-28 | Touch input follows what the device can do (`navigator.maxTouchPoints`, `any-pointer: coarse`), not the 900px layout breakpoint. Both handler sets run on a hybrid, and mouse events synthesized within 400ms of a touch are ignored. | A touch laptop or a tablet in landscape is 900px or wider, so it took the desktop layout and lost Spatial pan and pinch altogether. With both sets live, a background tap would otherwise step back twice, once per path. |
| 2026-10-28 | `qa/regress.sh` reports failures and exits non-zero: it caps checks with GNU `timeout`, `gtimeout` or perl's `alarm`, flattens each check's output before matching, and fails a check that crashes or prints no errors field. | GNU `timeout` is absent on macOS, so every check died with "command not found" and the run passed in seconds having tested nothing. A non-empty indented errors array also printed as a bare `"desktopErrors": `, indistinguishable from an empty one. |
| 2026-10-28 | Rule: V3 keeps the no-build app (no npm, bundler or modules in the app); V4 moves to a standard build step (React with Vite or similar, built by Vercel) as one planned migration with its own plan and approval. | The no-build setup was inherited and keeps V3 simple, but it blocks design-system tooling, Figma round trips, modules and a faster startup, which V4 needs. A planned move avoids risky partial migrations. |
| 2026-10-28 | QA checks move into the repo as `qa/`, development-only, with their own `package.json`. Vercel ignores the folder and installs stay out of Git. | Both agents can run the same checks, the checks change with the code, and they no longer live only in one chat's workspace. |
| 2026-10-28 | Development moves to Claude Code; AGENTS.md stays the single agent-neutral rulebook (CLAUDE.md only imports it), with docs/HANDOFF.md and this log. | Claude Code and Codex share one worktree and need the same rules without chat history. |
| 2026-10-27 | Batches ship to staging (`version/3.0`) first and reach `main` only on the user's explicit approval; one commit per ticket; a calendar recap after each approval. | The user tests on a phone before production and logs the work in a calendar. |
| 2026-10-27 | CHANGELOG times come from git, never estimates; merge status is updated in a follow-up commit before merging. | An entry once carried a time later than its own commit. |
| 2026-10-27 | Desktop Spatial cards get an invisible first button: Tab reaches the card before its Seen/Watchlist buttons, and Enter opens it. A card tabbed to off-screen glides into view. | Keyboard users could not open details from Spatial (List already worked). |
| 2026-10-27 | Scripts move focus only after keyboard input (`lastInput`); rings use `:focus-visible`; Escape closes one layer at a time; the desktop drawer is modeless. | A scripted focus move showed a focus ring after mouse clicks; the user found it confusing. |
| 2026-10-27 | Text tokens raised to WCAG AA (`--text-muted #8389a1`, `--text-dim #9ea4b8`; RT tag `#cc2a0a`). | Muted text measured 2.7–3.2:1. A colour fix keeps the compact layout. |
| 2026-10-27 | `og:image` / `og:url` point at production. Icons are rendered from the brand mark, with no studio imagery. | Crawlers need absolute URLs; production is the canonical address. |
| 2026-10-27 | The selected title in the ring is drawn larger on desktop only. | The phone ring is compact and already overlaps neighbours. |
| 2026-10-27 | A startup screen lives in `index.html` and `boot.js`; the locale files load before the CDN libraries. | Visitors saw a blank page while libraries downloaded and JSX compiled, and nothing explained a failed start. |
| 2026-10-27 | One normalisation, `MCU_I18N.fold()`, for search filtering, suggestions and highlights. | "Capitao" suggested titles that the filter then hid. |
| 2026-10-27 | Use React and ReactDOM production builds (pinned, SRI) and keep the no-build architecture. Precompiling JSX is left open. | Smaller download and about twice the pan frame rate on slow phones, with no workflow change. |
| 2026-10-25 | Desktop gets a List view beside Spatial (`desktop-list.jsx`, `52a1f60`): one row per title in the current sort, sortable column headers, the same details drawer. This reverses V3-SPEC §2 ("desktop is spatial-canvas only"). | Spatial is for exploring connections; scanning and comparing many titles needed a table. Recorded on 2026-10-30, when the planning documents were reconciled; the decision itself was made and shipped on 2026-10-25. |
| 2026-10-27 | Spatial canvas: no per-card GPU layers or backdrop filters, and composited only at ≥30% zoom (`LAYER_MIN_SCALE`). | iOS Safari reloaded the tab when panning zoomed out (out of graphics memory). |
| 2026-10-27 | Each phone sheet owns one history entry, so the browser Back button closes it. | Back left the site with a sheet open. |
| 2026-10-27 | Failed posters and portraits fall back to generated art or initials, remembered for the session. | Broken images showed spilling alt text and were retried repeatedly. |
| 2026-10-26 | Opening a title's rings hides unrelated cards instead of dimming them. | Dimmed cards behind the ring were distracting, especially in grid layouts. |
| 2026-10-26 | A guest sign-in reminder appears after 3 and 10 marks, once each. | A guest collection lives in one browser; a gentle prompt suggests signing in to keep and sync it. |
| 2026-10-26 | The Order menu became a two-state toggle. | It only ever had two options. |
| 2026-10-26 | Picking a character in search opens the character view (the pinned stepper), not a text search. | Users expect the character's titles, not every title matching the text. |
| 2026-10-26 | On phones, runs of seen titles fold into accordions on the All tab (closed by default, shared by List and Grid, remembered on the device). | Long seen stretches pushed unseen titles far down. |
| 2026-10-24/25 | The Notion V3 Tasks database is the backlog. Priority is the All tasks board's Backlog order, set by the user dragging cards; completion time and order follow fixed rules. | One source of truth for the user, Claude and Codex. |
| 2026-10-24 | Display preferences are per device (localStorage); filters and search start fresh each visit. | Nobody returns to a silently filtered catalog; there is no account schema change. |
| 2026-10-25 | English and Brazilian Portuguese; every UI string is a locale key, and search matches all languages. | The user's audience includes Brazil; this keeps adding languages cheap. |
| 2026-10-24 | Phases 1–5 are Google sign-in only. Email/password is Phase 6, deferred until a custom domain (for transactional email), its own plan and explicit approval. | Email delivery and account linking need a domain and careful design. |
| 2026-10-24 | Supabase free tier: accept pauses, no keep-alive automation. | Low traffic; avoid automation that works around the free tier. |
| V3 start | Keep the browser React/Babel architecture: no npm, bundler, router or ES modules; pinned CDN scripts with SRI; permanent catalog title ids. | Anyone can run it with a static server, and links and stored collections never break. |
