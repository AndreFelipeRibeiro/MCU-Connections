| 2026-11-01 | **Tailwind's preflight reset is scoped to `.v4`** while V3 and the design system share the page. `src/preflight-v4.css` is Tailwind 4.3.3's preflight with every selector limited to `.v4` and its contents; a converted surface opts in by putting `v4` on its root, and portaled components carry it themselves. | Loaded globally, the reset changed 166 computed properties on V3 elements — line height on every element, icon alignment, button fonts, default border and outline colours — found by comparing every element's computed style before and after. Patching V3 back would take unlayered rules that also override the new surfaces' Tailwind classes; leaving the reset out would break shadcn's components, which assume it. Scoped, V3 shows no computed-style difference at all and `design.html` renders pixel-identical. Temporary: when no V3 surface is left, Tailwind is imported whole again. | 2026-11-01 | **V3's ten colour tokens are renamed `--v3-*`** (653 uses, all in CSS), **Tailwind generates classes only from the files written for it** (`source(none)` plus `@source` in `src/index.css`), and the design-system tokens sit in the **base cascade layer**. | shadcn defines `--border` and `--accent` too, and two definitions on `:root` would let whichever loaded last recolour the other's. Scanning the whole project generated 3.8 KB of utilities from V3's class names: styles nobody wrote. With the tokens layered, V3's unlayered `color-scheme: normal` wins whatever the load order, so native controls stay as they were. |
| 2026-11-01 | The **pre-paint theme rule is injected by Vite into every page** (`THEME_PREPAINT` in `vite.config.js`) instead of pasted into each HTML file, and the **app now starts the theme** in `src/main.ts`. | `index.html` needed the rule as well as `design.html`: one snippet for every page keeps the copies at two (the module and the snippet) rather than one per page. |
| 2026-10-31 | The **contrast calculation** AGENTS.md has always asked for beside axe now exists and runs in the regression (`qa/test-contrast.js`). It measures the declared token pairs and the phase tokens in both themes, every piece of text on the design preview in both themes, and the app's own text that axe returns as *incomplete* — against the background actually painted, found by making the text transparent and photographing the page. Accepted shortfalls live in the check's `KNOWN`, each with the ratio it was accepted at and why. | Only the axe half was ever running, and axe reports text whose background it cannot resolve as *incomplete* rather than as a violation, which `a11y-scan.js` passes. That is not an edge case: it is every piece of text over a pseudo element, a gradient or an image, and it is where the Spatial band labels live — below AA in phases 3 and 6 since V3 shipped, which the new check reproduces (4.17:1 and 3.83:1) and which is now its own ticket. Writing the accepted shortfalls into the check rather than a comment means a ratio that gets worse fails, and one that starts passing asks to be removed. |
| 2026-10-31 | Two **light-theme tokens are darkened from the library's defaults**: `--muted-foreground` 0.556 → 0.54 and `--destructive` 0.577 → 0.52, same hue and chroma. The **dark phase colours stay as V3 wrote them** although five pairs are below AA, and the band-label bug they cause stays open. | AGENTS.md says to start from the library defaults *and* that both themes meet WCAG AA, and where the two disagree the accessibility rule wins: Vega's muted foreground measured 4.35:1 on `--muted` and `--secondary`, and its destructive text 3.97:1 on the 10% tint it is always painted over. The phase colours are different in kind — they are art direction, not a library default, and Andre's call on 2026-10-31 was to leave them for the Phase 4 re-skin rather than tune them twice. |
| 2026-10-31 | The **theme mechanism** is `src/theme.ts`: `dark` on `<html>`, following `prefers-color-scheme` until the visitor overrides it, the override stored under `mcu.theme` and *removed* to go back to following the system, with each page repeating the rule inline to set the class before first paint. The app does not call it yet. What a visitor clicks to override it is the Dark/Light ticket; the preview's three buttons are the preview's own. | "Follows the system until overridden" only works if not-overridden is a state the code can be in: the preview's first version wrote `light` or `dark` to storage on load, so a visitor who never touched the control was pinned to whatever their system said the first time they looked. The mechanism also has to survive storage throwing (private windows), the system changing its mind while the page is open, and another tab switching. The app stays out because it still serves V3's stylesheets, which are dark whatever class `<html>` carries — wiring it there would announce a preference the app cannot honour. |
| 2026-10-31 | The TypeScript conversion runs at **full `strict`**, and the files not yet converted carry an explicit `// @ts-nocheck` header naming how many errors each still has. No `any` is written to reach green, and `npm run typecheck` is green from the first commit. TypeScript is pinned to **5.9.3**, not the new 7.0.2. | The ticket asks for a deliberate strictness setting and warns against a pass that reaches green by spreading `any`. Measured first rather than guessed: 2,679 errors at full `strict`, 1,284 with `noImplicitAny` off, and **626 even with `strict` off entirely** — so no setting reaches green and loosening would only hide work while pretending otherwise. A per-file opt-out keeps the setting honest at its strongest, makes the remaining work countable, and lets each file be converted and its header deleted on its own. 5.9.3 because 7.0.2 is a brand-new major (the Go rewrite) and a 10,000-line migration needs a checker whose verdicts are trustworthy more than fast — the same reasoning that kept React at 18. |
| 2026-10-31 | V4 stays on **React 18.3.1**. The design-system preview was built on React 19.3.1 earlier the same day; that is reverted. The module conversion therefore runs on exactly the React the app runs today, and a React 19 upgrade becomes its own ticket. | Once the app's own files start entering the bundle they stop using the CDN React and start using the npm one, so the npm version is no longer free. Converting the module system and the React major at once would break Phase 2's single claim, that behaviour is identical. The reason for choosing 19 was shadcn's components expecting `ref` as a prop — tested on 18 and the eight copied components render with no errors, since Base UI supports 18 and the components are ours to add `forwardRef` to if a later one needs it. |
| 2026-10-31 | The V4 build keeps a **documented test surface** for `qa/`: the app publishes `TITLES`, `CHARACTERS`, `GUIDES`, `MEDIA`, `WATCH`, `MCU_I18N`, `MCU_isReleased`, `MCU_GUIDE` and `MCU_credit` on `window` from one module, unconditionally. Three checks that execute `data.js` in Node import it from the source tree instead, and `watch-data` loads on demand at a stable unhashed chunk name (which also answers V4-PLAN.md §10 question 1). | 15 regress checks read those names inside the page, 3 read `data.js` from disk, and `test-watch` replaces `watch-data.js` over the network; all three break on conversion for reasons unrelated to the app. Keeping the surface leaves the migration with one variable, which is what makes "behaviour identical" provable. It is not dev-only, because a surface stripped from production would stop the checks exercising what ships, and it exposes nothing new — the catalog is already in the bundle. |
| 2026-10-31 | V4's component base is **shadcn/ui on Base UI**, starting from shadcn's **Vega** style (preset `base-vega`: Neutral, default radius, Inter, lucide) with light and dark themes; V4's own look comes later through Figma variables. Answers V4-PLAN.md §10 question 5. | Andre chose it after comparing shadcn/ui and Radix Themes side by side on their default themes, in both modes, with V3's card, drawer and phone sheet. shadcn copies its components into the repo, so all of them can be restyled, and it themes through CSS variables that map onto Figma variables. |
| 2026-10-31 | V4's build step lands in **plain JavaScript**, and the TypeScript conversion is a separate ticket and batch straight after it, before the design system starts (docs/V4-PLAN.md §3.1, §9). | Phase 2's only claim is "behaviour identical", certified by the regression suite. Types also buy little in this step: the conversion turns 43 globals into named imports and the bundler already fails on a bad import. Where they pay is component variants and token-typed props in Phases 3–5, so the conversion goes immediately after Phase 2 rather than "someday". The price is one extra pass over the files; the gain is that each pass answers one question. |

| 2026-10-31 | V4's design comes from Figma through the Figma MCP server, registered in `.mcp.json`. Figma is the source of truth for variables (colour, type, spacing, radius, motion) and components; code mirrors the variables as tokens in one place with the same names, and components use tokens rather than values copied out of a frame. Design tickets link their frames in a **Figma** field and are read from the link, not from a description. **Where a frame and the accessibility, keyboard, contrast or localisation rules disagree, the rules win** and the difference is raised on the ticket instead of being copied silently. | Andre owns the art direction and the Figma file; agents own faithful, accessible implementation. Working from links rather than descriptions removes the retelling step where detail is lost. Naming tokens after the Figma variables makes a design change a token change instead of a hunt through components. The precedence rule exists because a frame cannot show focus order, Escape layering, a screen-reader name or how a string grows in Portuguese — so a frame that conflicts with those is incomplete, not a decision to follow. |
| 2026-10-28 | Portraits resolve through the credit, not the character. `MEDIA.performers` maps a performer name to a TMDB profile path; a row uses the character's portrait when the credited performer is the default, the performer map when it is not, and **no photo** otherwise. | Correcting the names alone left the right name under the wrong face, which is worse than both being wrong together. | 2026-10-28 | Manual panning ends with a light inertial glide instead of stopping dead, on both the mouse and the touch path. Any press, touch or wheel on the viewport stops it exactly where it is, a slow release does not throw, and `prefers-reduced-motion` disables it. | Asked for: the sudden stop made the Spatial canvas feel unrefined. This **reverses** the earlier rule that manual pan must stay instant, so the comment beside `glideTo` was rewritten rather than left contradicting the code. What that rule protected still holds — the canvas is never moving when you reach for it. A drag now settles a moment after mouseup, so checks that snapshot a camera position must wait for it (see `settleCanvas` in qa/test-camera.js). |
| 2026-10-28 | A performer credit belongs to the title, not the character. Titles may carry `credits` (character id to performer) and `CHARACTERS[id].actor` is only the default. A performer pins as themselves unless they are that character's whole run. | One `actor` per character leaked the current performer into every title: Iron Man credited Don Cheadle as Rhodes, The Incredible Hulk credited Mark Ruffalo and Harrison Ford. Keeping the credit on the title leaves the character's identity, colour and connection thread untouched. The pin rule follows from it — Terrence Howard plays Rhodes in one title of eleven, so pinning him must not open the other ten. |
| 2026-10-28 | Escape clears the pinned character or performer, last in the ladder (after the search box, menus, dialogs, sheets, the pair view and the details). The details rung and the pin rung share **one** listener. | The widget could only be dismissed with its ×. Two listeners broke the one-layer-per-press rule: both see the same press, React re-renders between them for a discrete event, and a listener added to `window` during capture is still called when the event bubbles back to it — so the second ran with a fresh closure, saw nothing in its way, and closed the pin under the details. |
| 2026-10-28 | A pinned subject is either one portrayal or a performer. Picking an actor who plays several characters pins the **actor**: the union of their own roles' titles, named as themselves with their characters underneath. An actor with one role still pins as that character, and picking a character still pins that portrayal. | Making `pickPerson` refuse multi-role actors removed the pinned widget for Jonathan Majors, Hayley Atwell, Paul Bettany and Robert Downey Jr. (who had never had it, two separate identities), which was a worse trade than the rule it protected. A performer's own titles are the titles they are actually in, so exact portrayal still holds and no result implies another actor's work. |
